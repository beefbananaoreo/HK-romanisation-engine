# HK Romanisation Engine

This repository currently contains the bounded CHG-050 Stage-0 contract materialisation for HKLANG:

- packet v1.7 / public contract `5.0.16`;
- generated serialised schema version `1.0`;
- executable non-linguistic validators and structural tests; and
- the bounded same-ID no-op import validator correction documented in [`docs/CHG-050-NOOP-VALIDATOR-CORRECTION.md`](docs/CHG-050-NOOP-VALIDATOR-CORRECTION.md).

The present repository scope is the contract/schema/validator boundary. It is not a claim that formal Stage 2 is closed, S2-P6 is authorised, or Reader integration is ready.

## Requirements

- Node.js 24 or later
- Python 3.12 or later for the static obligation check

## Verify

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run verify:step1
node scripts/check-surface-delta.mjs
python3 scripts/check-obligations.py
python3 scripts/test-obligations.py
```

The [CI workflow](.github/workflows/verify.yml) runs these checks on clean Linux and
Windows checkouts using Node.js 24 and Python 3.12, and rejects tracked-file drift.
It invokes the selected Python 3.12 interpreter as `python` on both platforms.

`npm run verify:step1` regenerates the public contract and schema, type-checks the complete affected graph, runs all bounded structural tests, and checks the generated bytes and stable test output.

The same command runs the test reporter's regression checks. Skipped, TODO, cancelled,
and failed tests cannot satisfy the verification gate. Run the Python obligation check
without `-O` or `PYTHONOPTIMIZE`, because its integrity checks require assertions.

Git preserves LF line endings through `.gitattributes` so generated bytes, recorded
evidence, and packet hashes match on Windows and Unix checkouts.

The [validation audit](docs/CONTRACT-VALIDATION-AUDIT.md) records later bounded
corrections, their packet authority, compatibility effects, and the remaining
